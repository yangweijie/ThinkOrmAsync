# 2026-11-26

## with() 关联预载 + cache() 异步路径修复

- 新增 `src/AsyncRelationLoader.php`：归一化 with() 写法，用 ThinkPHP 原生关联对象 +
  `fetchSql(true)` 生成 SQL 后交给 AsyncQuery 批量并行执行；嵌套关联按层级推进。
  HasOne/HasMany/BelongsTo/BelongsToMany 走异步快路径，Morph*/Through 走原生
  `eagerlyResultSet()` 降级。belongsToMany 分组必须用原始行（模型构造会过滤 pivot__ 字段）。
- 新增 `src/AsyncQueryCache.php`：异步/立即两条路径共用缓存读写，cache(true) 用 SQL 指纹 key。
  命中缓存的查询不进异步批次；写回的是原始结果集。缓存未配置时静默降级。
- 修改 `src/AsyncQueryWrapper.php`：with()/cache() 不再丢弃参数，暴露 getWithOption/getCacheOption；
  buildQueryKey 排除 with/cache 避免序列化闭包报错。
- 修改 `src/AsyncContext.php`：addQuery 记录缓存命中与关联配置，execute 跳过缓存命中的 SQL、
  写回缓存、主体结果落地后执行关联预载。
- 新增 `tests/integration_with_cache_check.php`：SQLite 内存库独立校验脚本，15 项检查全通过。
- 更新 FIXES.md / README.md。

验证命令：`php tests/integration_with_cache_check.php`。
环境注意：PHP 8.5 下 composer 锁文件里的 pest 2.x 不兼容，测试用独立脚本而非 Pest。
